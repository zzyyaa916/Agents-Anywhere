# 执行中消息与 Windows 项目选择核查 / 修订方案

1. 原 Web/Desktop 的 running 状态禁止提交，主按钮切换为停止；Server/Codex 已有运行中 steer 接口，客户端未接通，Claude 未提供该能力。
2. 用户确认最终交互：按发送先把消息放在输入框上方排队；支持即时补充的 Agent 才有「立即补充」。队列在当前任务结束后依次派发，停止任务暂停队列。复用现有 messages/steer API、能力判定、附件引用和 clientMessageId，补充时保留 running 状态，保留独立停止按钮。
3. 队列是当前客户端草稿，按服务器、用户、会话隔离保存在本地，不跨设备同步；恢复后默认暂停，发送失败/结果未知保留供人工确认，不自动重放。保存失败不清空草稿；审批、计划审阅、离线、未接管、归档期间不自动派发。
4. Windows 路径选择器把 C:\Users 的上级生成为 C:，这是盘符当前目录而非盘符根目录。复用已有 breadcrumb 路径逻辑保留 C:/，盘符根再用已有 fs/list 的空 path 请求显示所有盘符；未知 deviceOs 时从实际返回路径识别 Windows。
5. 用量：用户确认独立登录和 Agent 配置已完成，随后用量已恢复；本轮不修改采集来源、60/300 秒门禁和退避，不增加真实账号探测。使用空白临时 Codex Home 验证真实 SDK initialize/account/read 成功，账户为空符合预期，不读真实凭据。
6. 新会话：用户确认最后有回复，表现为响应慢，不作为已证实的状态机卡死处理，不擅改超时、模型、代理或终止任务。
7. 客户端内部改动 PATCH 2.5.3；Connector 保持 2.5.2，Server 保持 2.5.1，无新 API、数据库或冻结契约字段。只构建 Windows/macOS，不开发 iOS。不重启官方 Connector；instabox1 离线排查已按用户要求搁置。
