# Android Fork 现状核查与实施方案

日期 2026-11-10。用户最新授权：完整接入新增功能并交付 Android APK；iOS 仍不在本期。使用 ponytail 原则复用既有 API、能力模型、组件与持久化，不新增账号凭据链路。

## 与原说明书及当前代码的差异

1. 原说明书 §2 排除原生 Android；用户本次明确扩展范围。现有 Kotlin/Compose 客户端版本 2.5.0 仅扩展协议版本接收，未接 P1/P2/P3 界面。
2. 原说明书称 Desktop/Web 共用一套界面，实际是两套 renderer；Android 是独立原生端，不能通过打包桌面网页自动获得功能。
3. P1 服务端已提供资源删除及项目删除预览；Android 只有归档，须增加确认、精确子会话计数、409 忙碌阻塞提示和列表刷新，不能在手机删除设备上的项目文件。
4. P2 已提供缓存 GET 和有节流的刷新 POST；Android 没有账号用量入口。圆形按钮展开显示账号去重结果、百分比、重置和更新时间。手机不读取原生 token、不直连厂商。
5. P3 服务端提供 limited/quotaLimit 和原会话恢复门禁；Android 没有等待/到点状态与重新检查。须解析并保留 quotaLimit，恢复后手动原会话发送，不自动重试、不创建替代会话。
6. 用户后续增加的消息队列只在 Web/Desktop 实现；Android 须支持运行中入队、FIFO、停止暂停、失败保留和显式 steer（按能力）；审批/计划审阅/离线/未接管门禁。关闭/恢复后暂停，不能借后台队列无条件执行。
7. 原说明书 §4.2 指定 Claude 私有 OAuth 用量接口，用户后续明确要求改为被动原生事件缓存。本期以 SDK RateLimitEvent 为来源：只白名单数值/时间入库，缺失比例不猜测，过期不重置成 100%，不为采集执行任务；保留 Codex 来源与最小间隔纪律。账户关联不读取 accessToken/refreshToken。
8. Android 使用官方 applicationId、回调 scheme 和更新 URL；必须独立包名/名称，禁止下载官方更新覆盖 Fork。登录使用内嵌 WebView 私有拦截现有 mobile OAuth 回调和 PKCE，移除官方 scheme 的系统级 intent-filter，避免两版互相唤起；复用在线 Server 已允许的 mobile client，不要求上线新 Server。默认自托管 Fork；账号由管理员创建，不新增公开注册。
9. APK 需要可重复的独立签名；签名文件/密码不入 Git 或日志。构建使用云端隔离 runner，APK 回到本机签名，保证以后同签名升级。
10. 已有模型渠道功能可由 Server 接收/保存 API key，P0 已报告与凭据红线冲突。本轮不扩展、不修改该链路，验收仅使用虚构凭据，不读取实际账号认证文件，不操作在线 Connector。

## 施工顺序与验收

先固定现状与包名/构建，随后依次接入删除、用量（含 Claude 原生缓存）、限额续聊、消息队列，再完成本地逻辑与原生构建检查。全部在本分支交付 APK；不更新线上 Server、Web 或 Connector，涉及新采集需要单独发布并标明最低 Connector 版本。复用已发布接口，不增加协议字段；若发现必要契约变化则先补契约。

验收覆盖删除取消/忙碌/项目计数、账号隔离与缓存缺失/过期、原生事件缺失与账号变化、原会话续聊、FIFO/失败/恢复暂停/附件/steer 门禁、Fork 并排安装与禁用官方更新。通过模拟网络与虚构原生事件验证，不做真实额度探测。APK/签名/哈希可验证；真实安卓手机安装、登录和任务由用户验收，不能以构建通过代替。
