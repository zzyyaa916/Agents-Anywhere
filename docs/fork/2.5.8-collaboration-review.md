# Fork 多 AI 改动审查与 2.5.8 交付

## 当前实现

Fork 已包含独立应用身份与原生配置目录、账号用量、消息队列、限额恢复、项目/会话删除，以及用户主动检查的应用内更新。多 AI 在此基础上增加任务组、独立 Git worktree、候选普通会话、分屏及代码快照交接，没有新增模型调度引擎。

此前多 AI 主要在 Web 测试线：原输入框支持 1～3 个 Agent 与分别配置模型/权限，后端有一次性派发及停止后的快照交接。主要缺口是首轮附件被禁用、统一输入等待全部空闲、缺少明确中文转发指令，以及桌面未同步入口。

## 本次补齐

- 多 AI 首轮复用普通会话的附件序列化与服务端持久化，文字和附件交付每个候选；任务组轮询不返回附件 Base64。
- 明确的「转发给 AI：指令」直接走既有交接 API，不增加来源模型调用；普通讨论不触发，目标不存在或重名时提示选择。目标可为原选 AI 或同设备其他运行中 AI。
- 转发包含用户指令、原始任务、已有提交及未提交/新增/二进制代码快照、约 24000 字符的最近对话，以及原始和最近消息中的附件。附件原件走附件通道，不拼成对话文字；同名同内容附件去重，数量超过 10 个或已存储文件不可读时明确报错。
- 统一输入进入各栏现有队列，空闲栏立即处理，忙碌栏等待；队列原有暂停、恢复、失败保留和即时补充逻辑继续有效。关闭分屏只隐藏，避免卸载组件后停止队列。重新进入任务组会恢复多次接力转发的完整链。
- 模型目录保留官方模型名称，权限及已知思考强度显示本地化中文；Runtime 自己提供的翻译优先。
- 桌面同步同一组组件；Android 通过应用内共用 Web 工作台提供多 AI，保留原生单会话。登录只注入配置服务器的精确 origin，附件走系统文件选择器，不提供 JavaScript 原生桥。

## 精简与边界

沿用现有会话、审批、文件存储、消息队列和 Git 快照，不新增依赖、数据库迁移或自动合并机制。交接创建新会话，不复制厂商隐藏上下文；Git 忽略文件不进入快照。执行中来源的转发指令先排队，停止后再建立固定快照；不强行截取仍在写入的代码。

自然语言入口位于多 AI 分屏，各栏普通会话输入、附件与补充仍使用原实现。离开工作台后本地队列不会在后台继续自动发送；重新进入沿用原有确认恢复逻辑。Android 使用内嵌 Web 界面，需要支持启动脚本的 Android System WebView。

安装包按维护者要求编号 2.5.8；配套 Server/Web/Connector 延续 2.6.0 API 测试线。原生客户端的 2.5.8 与 API 标识不能直接比较，接口配套见发布说明。
