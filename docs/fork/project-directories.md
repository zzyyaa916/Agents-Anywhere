# 项目目录与删除范围

手动创建项目现在选择的是父目录。用户填写项目名 `Demo`、选择 `/work` 后，Connector 创建 `/work/Demo`，Server 把实际规范化路径保存为项目的 workspacePath。Windows 同样创建所选父目录下的同名子目录。输入的项目名必须是合法的单层文件夹名，不能包含路径分隔符、跳级路径、Windows 保留名称或控制字符。

以前的逻辑只是把选定目录直接登记为项目，不创建子目录，并可能把同路径的已有项目改名。这会使选到工作区根目录的项目在完整删除时触发保护。现有项目继续使用原来保存的路径，不自动搬移、重建或扩大可删除范围。客户端在目录模式下新建尚未登记的项目也使用同名子目录；选择已有项目仍使用已保存的实际目录。原生会话自动发现或历史目录导入（manuallyCreated=false）保留已有目录关联，不创建额外层级。

创建需要工作设备在线：Connector 先创建目录并返回收据，再登记 Server 项目。已有同名文件夹不会被接管或清空。相同创建操作的收据支持重试，登记失败只回收本次创建且身份未变化的空目录；目录已增加文件或已被替换时保留数据。成功后释放收据。固定身份 Fork 为新目录授予 Codex、Claude、DSH 的定向读写与继承 ACL；上级目录只增加通行权限，不公开其内容。改显示名称不自动移动目录，后续删除始终使用保存的实际路径，不能根据新显示名称猜测路径。

删除项目时清理该项目的服务端记录、全部会话专属数据和绑定的整个项目子目录；保留所选父目录、兄弟项目与不属于本项目的数据。继续核对目录身份、符号链接和与其他项目的重叠路径，禁止删除用户主目录、Connector 工作目录、运行环境或系统目录。旧项目如果绑定了受保护目录，仍会拒绝完整删除，需先明确其实际目录和迁移方案。

同一项目的会话共用项目代码。删除单个会话只删除其附件、缓存、服务端数据、对应原生聊天历史，以及项目中 `.agents-anywhere/sessions/<sessionId>` 的专属数据（如存在）；保留项目代码、同目录下其他会话与其他会话的专属缓存。旧版 Connector 集中保存的附件和该会话专属 conversation 工作目录也要清理，不把这些目录误当成项目共用代码。原生账号凭据不在删除范围内。

Server、Connector、Web、Desktop、Android 和 iOS 的手动创建表单需配套更新。本次不改变数据库结构；旧 Connector 不支持新的目录创建 RPC 时明确失败，不把仅创建数据库记录视为成功。未自动修改现有项目或删除线上文件。
