# 2.6.2 限额恢复与安卓错误详情、消息排序修复

本轮从前次任务本地提交 `b5d2e1bcc` 恢复源码，保留已完成的 2.6.2 改动；仓库默认分支仍为旧 2.5.3，不能直接在默认分支打包替代本次修复。未修改线上服务、原生账号或配对。

## 修复行为

- Web / Desktop 的限额提示纳入会话详情；轮询或手动检查第一次读到 ready/stopped/resumed 时，复用既有实时恢复流程重读 Runtime 状态及能力，避免提示恢复而输入区仍停留在旧状态。
- 无可靠恢复时间且重新检查仍无法确认时，可显式点击「结束等待」，调用既有停止等待接口；不创建替代会话、不自动调用模型，随后由用户在原会话主动发送。真实厂商限额若仍存在，正常请求仍会返回新的限额错误。
- 等待期间暂停本地队列，恢复后不自动重放；超过重置时间的旧低额度缓存不继续显示为当前警告，也不把缓存数值伪造成 100%。
- Android 第一次读取已恢复状态也刷新快照，而非只处理 limited → ready 转换。
- Android 错误提示使用较长的系统 Snackbar 超时并提供「查看详情」；完整错误可滚动和复制，关闭后保留原输入。普通成功提示保留原短超时。
- Android 乐观用户消息只按 Timeline 排序，不再把包含元数据事件的事件游标混进聊天排序；回执前后保持用户消息在回复之前，按 clientMessageId 去重。
