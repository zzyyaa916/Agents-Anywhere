在此前 `6bbea47fe` 的限额恢复、Android 错误详情及消息排序修复上继续开发，保留前次所有改动。

## 用户反馈与处理范围

重启 Windows 后暂时显示环境正被 Desktop/子进程占用，稍后手动重试成功。这既可能是真实后台或安装任务尚未退出，也可能是遗留锁中的 PID 被复用；没有取得 Windows 进程记录，不能声称已确认是哪一种。

本轮补齐遗留锁识别：Windows 上已有 PID 仍须核对进程启动时间；若启动晚于锁文件写入时间，它不能是原持有者，可回收旧锁。为兼容粗粒度文件时间，保留两秒容差。真实仍存活的 Desktop/子进程继续阻止重建；权限不足、检查超时等情况不删除未确认的锁，不自动终止用户的 AI 任务。无需手动删除整个 Connector 环境。

## 待发送命令与回复重叠

原输入区、待发送队列、审批卡片绝对定位在聊天区上方，依赖 ResizeObserver 把测量高度写回 Timeline 底部留白；队列变高时存在可见内容落到浮层背后的窗口。

Web/Desktop 将整个输入区和审批区放回会话纵向布局，由浏览器直接给 Timeline 分配剩余高度；删除两套高度测量及手工底部占位，回到底部按钮跟随 Timeline 自身底边。已有滚动跟随仍观察真实视口尺寸，保持用户阅读旧消息时的暂停规则，队列仍有原最大高度及内部滚动。

## Windows 消息排序补齐

此前 `6bbea47fe` 的乐观消息排序修复仅覆盖 Android；桌面和 Web 仍把事件游标用于消息顺序。本轮同步改为只用 Timeline 消息顺序，保持发送后到服务端回执之间用户消息位于回复之前；共享函数同时覆盖新建会话、普通会话和分屏会话。

新增回归覆盖 Codex、Claude、DSH 的高事件序号、服务端回执去重、快照恢复、空 Timeline 和连续待发送条目；新增回归在旧桌面实现上失败，修改后通过。未重新构建安装包，已安装客户端仍需以后包含本修复的版本。
