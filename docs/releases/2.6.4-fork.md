# Agents Anywhere Fork 2.6.4（源码交付）

Connector、Windows/Mac Desktop、Android、iOS、Web、Server 与 DSH Bridge 源码版本统一为 2.6.4；Android versionCode 为 25，iOS build 为 14。本次只上传源码，不构建安装包、不创建 GitHub Release、不部署线上环境。

## Claude 双源手动用量

只有手动点击刷新才在指定甲骨文 ARM Connector 执行 OAuth 探针；没有后台、打开面板或撞限额探测，节点离线不故障转移。令牌仅在本机 Claude 身份下读取和使用，不上报或记录；User-Agent 使用实际安装的 Claude CLI 版本。

Server 按账号和窗口分别保留事件与探针最后有效数据，使用 Server 接收时间选择新数据，显示来源和年龄，不按时间清空。部分更新不覆盖其他窗口，失败不修改缓存。跨进程全局单飞，两次成功至少相隔五分钟；429 优先遵守 Retry-After，否则退避翻倍。第三次 429 熔断到次日 00:00 UTC，成功清零，解除熔断后恢复五分钟间隔且不自动请求。三端显示“今日探针已熔断，明日恢复”并禁用刷新。

当前方案替代此前未部署的自动探针方案；完整规则见 [Claude 手动用量探针](../fork/claude-usage-probe.md)。保留 2.6.3 的立即补充去重、完整删除与原生用量缓存修复，参见 [2.6.3 发布说明](2.6.3-fork.md)。

## Claude 运行中「立即补充」（透传）

Claude 运行时新增 `steer_turn`，把运行中的补充消息注入当前回合的实时 SDK 连接，由 Claude Code 在下一个工具调用边界处理，对齐原生行为；不新建会话、不新开回合。补充消息写入时间线并归属当前 `turn_id`，事件标为 `claude.turn.user.supplement`，与初始消息共用 `clientMessageId` 去重机制，原生回显不会产生重复项。

传输链路复用既有的通用透传能力：客户端 `POST /sessions/{id}/runtime/steer` → Server `steer_session` 校验 `session.steer` 能力并单点定序转发 → Connector `session.steer` RPC → `runtime.steer_turn`。因此本功能**无需改动 Server 与三端客户端代码**：Claude 的 `steerTurn` 能力打开后，Web / Desktop / Android 现有按能力显示的「立即补充」按钮会自动出现并可用，现有消息队列负责排队、顺序、撤回与送达状态。

可靠性与边界：
- **去重**：每条补充带客户端 `clientMessageId`，Connector 侧按回合内已注入集合去重；网络重试或重连重复下发不会执行两次，返回幂等结果。
- **权限弹窗**：存在未决审批（`response_required`）时，补充被拒绝（`claude_steer_blocked_approval`），绝不绕过或顶替弹窗，处理完弹窗后再发。
- **无活动回合**：会话未在运行时返回 `claude_no_active_turn`，不静默丢弃。
- **不吞错**：注入失败返回 `claude_steer_failed` 并回退去重标记，错误对用户可见。
- **功能开关**：工作设备环境变量 `AA_FORK_CLAUDE_STEERING=1` 开启，默认关闭。关闭时 `steerTurn` 能力不广播，客户端自动降级为「回合结束后作为下一条发送」的旧行为，无需发版即可止损（满足按运行时开关与降级要求）。
- **范围**：仅改 Claude 链路，Codex 一行未动，已跑 Codex 会话回归确认无影响；长活会话沿用工作设备上已有的 Claude 登录状态，不新增任何凭据读取、存储或上报。

本轮**仅改 Connector**（能力翻转 + `steer_turn` + 回合内去重 + 开关），Server 与客户端无代码改动；因此部署时只需升级工作设备 Connector 并在该设备开启开关，无需升级 Server 或重建客户端安装包。

未在本轮覆盖、留作后续：Connector 崩溃重启后对未送达补充做持久化对账恢复（当前行为是注入失败即明确报错，不静默丢失，但不跨重启续传队列）；时间线对「中途补充」的专门视觉标注与多端撤回/状态细节沿用现有共用队列 UI，具体表现以真机验收为准。

## 升级要求

Server、Connector、Web / Desktop / Android 需配套更新。先备份数据库，再迁移至 v2_59（包含 v2_58 完整删除清理列及 v2_59 双源缓存和持久化探针控制）。更新脚本支持现有 2.6.3 来源，不回滚到不兼容新 schema 的旧镜像。

所有节点默认禁用探针；仅在甲骨文 ARM 配置指定 Connector ID、机器指纹及受控代理白名单。Server 只配置目标 ID，不接触 OAuth 凭据。源码上传不会更改线上配置、安装版本或启动探针。iOS 尚无用量面板，本次仅同步版本。
