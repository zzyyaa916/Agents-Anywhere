# 2.5.0 分叉版 P3（未发布）

基于 P2 2.4.0，包含删除、双 Runtime 用量、限额恢复后原会话继续。沿用官方跨端 MINOR 规则，所有端元数据 2.5.0；原生移动端不加新界面，Android 数据接收允许 1.2。

## 行为与兼容

- Codex / Claude Code 的终止用量错误进入持久 limited，泛化 429、网络和普通错误不推断为账号额度；Claude 兼容助手错误块与错误结果正文。
- 对应账号缓存中多个窗口都耗尽时，取最晚的未来恢复时间；无可靠时间就显示未知，不猜恢复时间。
- 到点读时计算 idle，SQL 事实及缓存一起投影；用户手动继续，发送保留原 externalSessionId，缺失或变化时 409。成功续发后消费等待状态，后续普通错误保持原有行为。
- 重新检查走 P2 采集门禁，必须是同一来源绑定的新鲜同账号快照且不再耗尽才提前解除等待。已知账号变化不使用另一账号窗口。缺少原账号标识时保守保留等待，可停止等待后手动尝试原会话。
- 中断标注以平台系统项写入时间线，并在 Runtime 全量同步时保留；原始失败记录保留。删除仍清除所有业务数据。
- 使用新平台契约 protocol/1.2，冻结 1.0/1.1 导出字节保持不变。limited 实时事件标为 1.2，恢复后的实时事件仍以 1.0 交付；Web/Desktop 兼容三版。官方 iOS 源码可容忍未知 limited 并读取恢复后的 idle，但这不能替代真实 App 实测。
- 可选自动重发未实现，没有自动重发开关、定时重发或隐式重复任务。

## 升级与回滚

1. 在测试部署先验证；备份 PostgreSQL 与附件目录后，按官方部署流程将 Server、Connector、Web、Desktop 一起替换。生产环境未在本任务中修改。
2. 数据库从 P2 升级至 v2_56；从官方基线则依次执行 v2_54/v2_55/v2_56。默认后台用量采集沿用 P2，凭据只在工作设备直连提供方使用。
3. 回滚至 P2 时先停止新 Server，备份后执行 Alembic downgrade v2_55，再部署 P2；迁移会将 limited 持久状态改为 idle 并移除限额字段。安全时间线中断标注仍可由旧客户端显示。原生会话 ID 不会被迁移清除。
4. 使用仓库手动 Fork Desktop test installers 工作流，在 Windows/macOS 各构建一次；未上传、签名、公证或替换用户客户端。新版本继续禁用官方安装包下载。
