## 修复

- Web/桌面登记联立路由，点击侧栏、新建多 AI 后进入联立工作区及重开应用不再被当成未知登录路由。
- 固定身份的 DSH 在描述文件未改变时也重建 Bridge ACL；描述文件新建/更新后再授权。修复在线程中执行，子进程有超时；非 Fork 不执行该授权。
- 固定身份的 Claude Code 通过相同 broker 的只读 `auth status` 获取稳定身份，修复账号文件不可读导致用量观察器失效；补齐运行实例包装层遗漏的观察器转发。身份读取移出事件循环，切换账号后拒绝旧连接事件。仅显示真实 SDK 原生事件，首次无有效事件仍显示等待，不制造额度。
- Claude Code 和 Codex 的本地附件副本向对应固定 AI 账号授予目录穿越和文件读取权限，复用 DSH 已使用的 ACL 工具；拒绝链接路径，保留各自原生账号和私有配置隔离。DSH 保留已有独立附件暂存与授权。
- 更新下载支持续传、长超时和重试，完整 SHA256 通过后才产生最终归档；也可以跨机器下载并校验后传到目标服务器。Connector 使用完整独立环境升级，支持旧普通目录和已有环境链接，保留切换与启动失败回滚，检查配对和 Fork 运行配置。

## Android

新建会话在原 Agent 选择器勾选 1–3 个 AI；单选沿用原有会话流程，多选在同一页配置各 AI 模型/思考强度/权限并输入首轮任务和附件，发送后进入已有分屏。不再显示上方独立「原生多 AI 工作台」入口。

普通会话提供小转发按钮，也识别多目标文字命令；转发携带服务端来源上下文与附件，在来源项目创建目标会话。来源运行时禁用；部分失败后同一操作按稳定目标标识重试，已投递和未知状态不自动重放。运行配置按实际能力加载，附件仍受目标能力和大小限制。

会话列表提供「联立会话 / 恢复多 AI 任务」入口，可选择同项目两个不同 AI 的已有会话；复用原会话聊天、消息队列和分屏，统一输入按各会话状态发送或排队。选择、收起状态、草稿和部分接收状态按服务器+用户隔离保存；返回后恢复，不自动发送草稿。历史任务组有独立恢复入口。

## 下载、校验与部署

发布后从本 Fork 的 `v2.6.2-fork` 预览发布页取得实际资产和 SHA256SUMS；不得复用 2.6.1 摘要或将旧包改名。使用发布页面提供的可信完整摘要：

```bash
bash scripts/fork/download-preview.sh 2.6.2 <发布记录中的完整SHA256> ./Fork.Server.Web.2.6.2.update.tar.gz
```

下载失败保留 `.part` 以便重试；服务器不支持续传时从头下载，校验失败不安装。目标机器到 GitHub 较慢时，在连接正常的机器下载并校验，再使用既有 `ai-ssh` 运维身份传输，目标端再次校验相同 SHA256 后解压到新的目录。解压后运行 `python3 deploy.py verify`；这一步不修改服务。

Server/Web：在维护连接确认空闲后执行 `python3 deploy.py server`，保留原有数据库备份、镜像和失败回滚；独立核对公网健康版本、页面内容及登录/转发。

Connector：先检查运行任务并确认空闲，在已授权的 OTP 维护连接停止 `agents-anywhere-fork.service` 后运行 `python3 deploy.py connector`。升级脚本拒绝停止在线任务，不自动更换配对或复制原生账号。若预安装失败，原服务仍处于操作者停止的状态，须在维护连接重新启动旧服务；切换后失败则自动尝试回滚并启动旧环境。必须独立验收 DSH 重连、各 AI 附件读取及下一次正常 Claude 原生事件采集，不能仅凭 service active 判定全部恢复。

GitHub 发布、腾讯云 Server/Web 部署和各设备 Connector 升级是不同交付项。本页末尾的构建记录为准。
