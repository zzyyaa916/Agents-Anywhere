# 2.3.0 分叉版 P1：历史删除（待实机交付验收）

基于上游 main `8fef5e3b967dfd719f4712749b3b3a3ffe4736a2`（2.2.0），按官方跨端接口变更规则升 MINOR。本版本尚未发布到上游；P2 用量与 P3 续聊未实施。

## 用户可见变化

会话菜单可以删除单会话；项目菜单可以删除项目及全部会话，包含归档与分页未加载的历史。项目确认显示 Server 精确计数并要求输入项目名，数量变化时必须重新确认。消息、Timeline、附件、缩略图、会话关联数据与缓存清理；运行、待批准、排队、停止中或尚有活动任务/目标时返回 409 并给出会话 ID。非所有者删除返回 403，重复删除返回 404。

客户端确认取消不产生删除请求；成功后即时移除本地列表并退出已删除会话。Connector 的原生线程、原生历史和工作目录保留，Server 最小删除标记抑制自动重导入；另保留操作审计，不保留会话正文或凭据。

## 配套版本与迁移

- 本分叉 Server、Web、Desktop 使用 2.3.0；Connector、DSH、Android、iOS 按官方规则同步 MINOR 元数据，本期未增加移动端 UI、未修改 Connector Runtime。
- 新 API 与兼容语义见 [历史删除 API](../api/history-deletion.md)。沿用官方项目 DELETE，`detachedSessions` 保持 0，新增 `deletedSessions`；新增单会话 DELETE 和项目删除预览。
- 数据库升级 `v2_53 → v2_54`，只新增最小删除标记与审计表。只通过官方迁移命令升级；禁止直接改生产表。
- 停止待升级 Server 的写入后，备份 PostgreSQL **及对应附件目录/对象存储**，演练恢复，再迁移和部署测试环境；验收后成套替换生产。不要停止本机当前连接用的 Connector。
- 在独立开发虚拟环境运行：`server/.venv/bin/python -m agent_server.infra.db.migrations upgrade`（在 server 目录则 `.venv/bin/python`），数据库地址仅在本机环境变量中配置，不放进命令记录、提交或聊天。继承 uv 环境变量时必须明确项目自己的虚拟环境路径，不能复用运行 Connector 的环境。
- Schema 降级在停止写入后使用官方 Alembic `downgrade v2_53`；它只撤销新表，不找回已经删除的内容，而且会失去防重导入标记。需要恢复数据时从成套备份恢复，不能用 downgrade 代替数据恢复。

## Desktop 构建与更新

`desktop-workbench/config.json` 的 `updates.downloadUrls` 已清空，仍沿用官方更新服务，但不能从应用中下载官方包覆盖分叉。后续有自己的发布地址时再配置。

官方 `dist:mac` 必须在 macOS 运行，`dist:win` 必须在 Windows 运行；Linux 上通过 renderer 构建不代表安装包、签名或真实安装已经验收。提供手动触发的 [原生打包工作流](../../.github/workflows/fork-desktop-build.yml)，在 macOS/Windows runner 上复用官方脚本，产出未签名的测试安装包，不读取用户的 Agent 登录凭据，不自动发布 Release、不部署。须将代码放进用户自己的 fork 后手动运行；本机没有 GitHub 登录，当前未推送或执行该工作流。

本地命令：macOS `corepack yarn dist:mac --arm64`；Windows `corepack yarn dist:win --x64`，均在 desktop-workbench 目录。正式签名/公证按官方 README 在构建机本机完成，不把证书或账号密钥放入仓库。

## 已知限制

- 生产部署、备份恢复演练、Win/Mac 安装包实际构建与安装、官方 iOS 列表刷新尚待对应环境实测，不能算作完整交付通过。
- SQL 与文件后端没有分布式事务。存储失败返回 503，SQL 回滚保留对象以便重试，但已清理的文件无法回滚；故障期间需重试删除。SQL 成功但缓存清理失败会保留待清理记录，重试请求或后台恢复继续清理，不报告成功。
- Server 按收到的 Runtime 状态和活动任务拒删；工作设备上尚未同步的新原生活动无法由离线 Server 实时确认。
- 保留官方平台活动统计的聚合口径；硬删内容不抹去既有使用统计事实。数据库中仅删除抑制标记/审计和统计事实可继续包含对象 ID。
- 已报告的官方模型渠道 Server 接收/保存/下发 Key 流程未在 P1 改动，本次没有调用该流程；不能据此宣称整套上游全站满足凭据本机红线。P2 的 Codex/Claude 凭据不得复用该链路。
