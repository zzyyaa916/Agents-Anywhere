# Fork 2.7.3 修复批次

基线为 `fix/con+be/upgrade-2.7.1` 的 `4c089a78`，包含 PR #20–#22（在 2.7.2 的 `924e330d` 之上）。2.7.3 只做 Server/Web 的修复，没有新增数据库迁移。

## 主要修复

- 时间线序号放置：连接器重启并重新编号后，新消息一律追加到会话末尾，不再按原序号插回历史；短会话也能识别出重启。迟到几条消息仍按原位放置。初始同步沿用连接器自身编号，范围内未被占用的序号原样落库（含负数边界）。（PR #20）
- 时间线序号越界：批次里合法的序号（例如顶到列上限的位置）落库时原样保留，不再被算成“上限 + 1”导致整批写入失败；真正无位可放时仍按既有语义报错并整批回滚（会话序号不变、冲突条目不落库）。（PR #20）
- 删除拒绝的翻译：设备以“目录与其他项目重叠”等原因拒绝清理项目目录时，接口返回设计好的 503 和对应文案，可按原流程重试；不再把拒绝透传成内部错误。连接器的保护行为不变，嵌套目录保持完好。（PR #21）
- 用量探针测试：Claude 用量快照的用户外键在测试夹具里按登录后的真实流程补建用户行；产品代码未改。（PR #22）

## 验证

- **数据库集成测试已补跑**：合并后全量 **1276 passed / 0 failed / 14 skipped**（一次性 PostgreSQL 库，`agents_anywhere_test`）。
- 上次记录为 flaky 的 `tests/test_session_inventory.py::test_inventory_derives_untitled_session_titles_in_constant_queries`（查询次数断言）已登记单独处理，不计入本版结论。
- 本次只做 Server/Web 更新包，Android APK 与桌面端不在本轮。

## 部署方式

沿用手动部署方案：停旧 Server 写入进程，备份数据库与文件存储，用新镜像/新包替换后启动，检查 `/api/v2/health/ready`，再恢复入口流量与 Connector。迁移语义与 2.7.2 相同，本版不需要额外迁移。

## 产物边界

- 本批构建 Server/Web 更新包（`Fork.Server.Web.2.7.3.update.tar.gz`）与包内 Connector wheel。
- 打包脚本 `scripts/fork/upgrade-legacy-connector.py` 的安装校验原先写死了旧版本号，与包内 wheel 不一致；本版改为随发布版本号取值。
- Android APK、Mac/Windows 安装包不在本轮范围。
