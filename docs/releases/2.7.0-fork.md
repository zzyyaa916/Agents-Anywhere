# Fork 2.7.0 用量可靠性修复

基线为 origin/fix/2.6.7 的 794bde30；该仓库 main 与默认分支落后于此基线，按用户要求使用最新分支。

用量契约增加未激活窗口的 null 重置时间、parseWarnings、parse_error 与 auth_expired，按版本规约升级所有端 MINOR 至 2.7.0。Server、Connector、Web、Desktop/Android 用量界面须配套升级；iOS 没有该面板，仅同步版本。没有数据库 schema 迁移。

缓存已按窗口保留独立 received_at，本次保留失败窗口时间并单独保存告警；null 清除旧重置时间。只有连续限流翻倍，本地间隔上限 1800 秒；Retry-After 优先，保留连续三次 429 的次日熔断。

凭据锁只保护合作进程；外部登录在最后比对与 rename 之间仍存在极小竞争窗口，不宣称根除。刷新成功而写回失败时返回 write_failed_after_refresh：可能需要在该机器上重新登录一次 Claude。

交付包含由 scripts/fork/build-preview.py 生成的 Server/Web/Connector 更新包与 manifest，使用原升级脚本；助手保持 root 属主且不可组写。本次不执行 ARM 部署，也不运行真实 OAuth 刷新。

已验证：Connector 用量相关 76 项、Server 无数据库策略 4 项、Web/桌面用量面板各 11 项通过；Web 类型检查及 protocol:check 通过。数据库集成测试未跑：未配置 AGENT_SERVER_TEST_DB_URL，测试不能使用生产库替代。Android/iOS 安装包未构建。
